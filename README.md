# OfferFolio · 求职橱窗

> 由 **EckyStudio** 发起与维护。

**把简历发出去，不再石沉大海。**

> 带后台的开发者求职作品集 —— 网页里改内容，一键发布静态站；每条经历都能挂上可验证的证据，同时记下每一位访客读了什么、读了多久。
>
> *A portfolio that tells you who looked, what they read, and for how long.*

OfferFolio = **Offer** + **Folio**（portfolio 的词根，本义"一叠可携带的纸页"）。名字就是目的：作品集不是终点，拿到 offer 才是。

---

## 为什么做它

投递季最稀缺的不是机会，是**信息**。

你把 PDF 发给五家公司，然后就什么都不知道了：HR 到底点开了没有？他是认真看了你的项目列表，还是划到最后一页找邮箱？哪一家第二天又回访了一次？

传统作品集模板解决的是"展示"。OfferFolio 补上的是另一半——**展示 + 反馈闭环**：

给每个投递对象发一条专属链接，谁点了、停留多久、在哪个板块停最久、有没有下载简历，后台一目了然。

这个信息是可以直接带进面试的。你知道对方在你的"量化交易系统桥接"上停了四分钟、完全没翻 Android 那段，开场就能顺着讲。**这是单向投递给不了你的信息优势。**

---

## 更深一层的痛点：信任建立不起来

简历是一次**有损压缩**。十年经验压成一页 A4，压掉的全是证据：你写"精通 Android Framework"，HR 无法验证；他一天看两百份简历，每场面试三十分钟，最后只能靠学历、公司名气、话术流畅度这些**代理指标**下判断。

于是双方都难受：你被低估，他被将就。真正决定录用的从来不是"他简历写了什么"，而是"**我有没有足够证据相信他做得出来**"。

所以 OfferFolio 对内的定位不是"更好看的作品集"，而是**一条可下钻的证据链**：

```
第一层  结论     一句话 + 一个数字        → 让 HR 10 秒判断值不值得往下看
第二层  说明     做了什么、怎么做的、难在哪 → 让技术面试官判断深度
第三层  证据     代码 / 在线 demo / 原始截图 / 提交记录 / 可查编号 / 第三方背书
                 → 让怀疑的人自己验证，不用等你在面试里解释
```

大多数作品集只做到第一层，少数做到第二层。**第三层是空的**——而那恰恰是信任的来源。

配套的可信度设计：

| 手段 | 为什么有效 |
|---|---|
| 每个项目挂**可点击的原始证据**（仓库、commit、发布记录、线上地址） | 把"我说"变成"你可以查" |
| 经历带**时间戳与量化口径**（不是"优化性能"，而是"延迟从 8ms 降到 1.2ms，压测脚本在此"） | 可复核的数字才有说服力 |
| 开源板块直连 GitHub，**提交热力图与贡献记录自动同步** | 第三方数据，改不了 |
| 敢写**失败复盘与踩坑记录** | 只报喜会触发怀疑，主动暴露缺陷反而增信 |
| 推荐语带**推荐人可点开的身份链接** | 匿名好评等于没有好评 |
| 站点内容与 PDF 简历**严格一致**（同一份数据源导出） | HR 一定会交叉比对，对不上就全盘崩塌 |

而这一层和访客雷达其实是**同一个闭环的两端**：雷达告诉你对方在哪块信息前停住了、哪块直接跳过，你就知道该补哪份证据给他。信任很少在一次面试里建立完成，它是几轮"对方存疑 → 你精准补证"累积出来的。OfferFolio 要做的，就是把这件事变成可执行动作，而不是靠临场猜。

## 四个主打

| | 你能得到什么 |
|---|---|
| **快捷** | 一条命令起服务；后台填表式编辑，不用碰代码、不用重新部署；模板 + 板块开关，十分钟出一份能投递的站点 |
| **丰富** | 14 类内容板块自由增删排序；技能矩阵、项目卡片、经历时间线、开源仓库自动同步 GitHub、证书成就、演讲文章、双语切换 |
| **可信** | 三层下钻的证据链结构，每个结论都能挂代码、demo、原始截图、提交记录或第三方背书；内容与 PDF 简历同源导出，经得起交叉比对 |
| **实用** | 访客雷达 + 投递链接管理 + 阅读热力，把"作品集"从静态广告变成求职工作台；数据全在本机，导出即带走 |

## 核心能力：访客雷达

**每条投递一个专属链接**（`/r/7fa3c`），点开的瞬间就归属到具体公司，不靠 IP 猜身份。

记录下来的是这些：

- 首次打开时间、累计停留时长、回访次数与间隔
- **板块级阅读深度**：滚动到 25% / 50% / 75% / 100%，每个板块各自的停留秒数
- 关键动作：简历 PDF 下载、联系方式展开、外部项目链接点击
- 上下文：设备与浏览器、来源页面、时区与语言（**不存储完整 IP**）
- 实时提醒：HR 打开后立刻通知你，趁热跟进

**抗误报是这套数据能不能用的关键**，所以内置了清洗规则：只认执行了 JS 的真实访问、丢弃 2 秒以下的瞬时命中、过滤邮件安全网关与链接扫描器的预抓取、屏蔽爬虫与云厂商 IP 段。你不需要在后台里分辨"这是真人还是扫描器"。

## 展示能力

内容板块（可增删、可排序、可按岗位切换权重）：

```
自我介绍      技能矩阵      工作经历      教育背景
精选项目      开源仓库      成就证书      演讲与文章
成长时间线    数据亮点      推荐语        联系方式
简历下载      暗色 / 双语
```

开源板块直连 GitHub，自动拉取仓库与贡献记录；简历 PDF 可后台替换，下载行为本身也是一个被统计的高价值信号。

**每个条目都支持挂证据**：外部链接、代码地址、在线 demo、原始截图、录屏、可查编号、第三方背书，任选组合。前台默认折叠到第二层，想看细节的人（通常就是那个技术面试官）自己点开——不占用想快速浏览的人的时间，也不亏待想深挖的人。

## 部署：本地优先，一台机器即可

OfferFolio 的首版面向个人本地部署：公开作品集和管理后台由同一个 Next.js 服务提供，SQLite 数据库存放在本机或 Docker 数据卷中。

- 本地开发无需独立数据库服务，内容写入项目目录下的 SQLite 文件
- Docker Compose 只启动 **一个应用容器**；不额外启动数据库、缓存或追踪服务
- 默认只绑定 `127.0.0.1`，适合先在自己的电脑上编辑和预览
- 静态站点导出、CDN 发布和访客雷达属于产品规划，首版尚未实现

## 和同类方案比

| | 后台编辑 | 访客记录 | 可验证证据链 | 静态导出 | 数据归属 |
|---|---|---|---|---|---|
| developerFolio 等模板 | ❌ 改配置文件 | ❌ | ❌ 自己排版 | ✅ | 你的代码 |
| 招聘平台在线简历 | ✅ | ❌ 平台不给你看 | ❌ | ❌ | **平台** |
| DocSend 类文档分析 | 部分 | ✅ 但面向文档 | ❌ | ❌ | 你的账号（SaaS） |
| **OfferFolio（规划目标）** | ✅ | 规划中 | ✅ 内建三层下钻 | 规划中 | **全部在你自己机器上** |

最后一列是刻意的：没有第三方分析 SDK，没有跨站追踪，数据不出你的服务器。

## 技术栈

| 部分 | 选型 |
|---|---|
| Web 框架 | Next.js 16.3.8（App Router） |
| UI | React 19.3.0 + TypeScript 7.0.2 |
| 样式 | Tailwind CSS 4.3.3 |
| 数据库 | SQLite，使用 better-sqlite3 13.0.3；WAL 模式 |
| 运行时 | Node.js 24 |
| 部署 | 本地 Node.js，或一个包含前台、后台和 SQLite 驱动的 Docker 镜像 |

版本按 2026-10-07 查询到的稳定版锁定在依赖文件中，升级时以兼容性和安全修复为准。SQLite 不需要单独的服务容器：本地模式使用 `./data/offerfolio.sqlite`，Docker 模式使用持久化数据卷。应用不接入第三方分析 SDK。

界面参考 [DeveloperFolio](https://developerfolio.js.org/#contact) 的作品集信息层级和联系区布局，重新设计为中文优先的响应式页面；这不是对原模板的逐像素复刻。

## 快速开始

### Docker 一键启动

```bash
git clone https://github.com/mynameyi/offerfolio.git
cd offerfolio
cp .env.example .env
```

编辑 `.env`，把 `ADMIN_PASSWORD` 改成长密码后启动：

```bash
docker compose up --build -d
```

- 公开作品集与管理后台共用 `http://localhost:5188`
- 后台入口：`http://localhost:5188/admin`
- SQLite 数据保存在 Docker 本地数据卷 `offerfolio-data`
- 停止服务：`docker compose down`；该命令会保留数据卷
- 备份数据库：`docker compose cp offerfolio:/app/data/offerfolio.sqlite ./offerfolio-backup.sqlite`

镜像只运行一个应用容器，不依赖数据库镜像。Compose 默认将端口绑定到本机回环地址，外网访问需自行配置 HTTPS 反向代理，并在 `.env` 中设置 `COOKIE_SECURE=true`。

### 本地开发

```powershell
git clone https://github.com/mynameyi/offerfolio.git
cd offerfolio
Copy-Item .env.example .env.local
npm ci
npm run dev
```

打开 `http://localhost:3000` 查看公开页面，`http://localhost:3000/admin` 编辑档案。数据库默认存放在 `./data/offerfolio.sqlite`。

## 关于隐私与合规

你追踪的对象是 HR 和面试官，这件事做得体面比做得聪明更重要。OfferFolio 的默认策略是：

- 站点页脚明示"本站记录匿名访问统计"，不做隐瞒
- 只存 IP 前缀或哈希，保留期默认 90 天自动清理
- 不做跨站追踪，不加载任何第三方分析脚本
- 数据全部留在你自己的服务器上

一句话原则：**用它来判断"该往哪个方向准备面试"，而不是用它去骚扰任何人。**
